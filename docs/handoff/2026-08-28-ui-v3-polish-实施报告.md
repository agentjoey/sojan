## 逐屏对照（owner 指令逐条）

**1) 去除黄历** — 删 `/calendar` 移动端黄历块（page.tsx 原 377-384）；`packages/core/src/daily/index.ts` 降级版 `auspicious/caution` 不再混入 `almanacYi/Ji` 前两条；locale 键 `calendar.almanac/yi/ji/none`（zh+en）删除。`almanacYi/Ji` 字段保留（TG daily API 形状不变）。⚠️ 已知代价（owner 已拍板接受）：TG 端若展示 auspicious/caution，内容同步变化。`fortune-images` 的「今日宜…」诗意 caption 按 owner 选定范围未动。

**2) 首页今日卡** — 根因：polish/meta 是写死 locale 的静态文案 + 候/日期是服务端 UTC 快照（ISR 最长 1h 陈旧）。修法：抽 `lib/useDailyFortune.ts`（流日 + LLM polish 按 档案×日期 缓存，自 calendar 原样搬出），首页与运势页共用；新增 server action `solarHouAction(dateStr)` 按访客本地日期算候（lunar 不进 `/` 客户端 chunk 的 bundle 红线不破）；无档案不渲染今日卡（owner 拍板）。首页卡的 dateNote 随之从「星期」变「农历日」，与运势页逐字同源。候标尺挂载后也经同一 action 覆盖，原 M7 注释量化的 6.6% 时区错位窗口消除（page.tsx 注释已更新）。服务端 prop 仍保留作 SSR 首帧/兜底。

**3) 胶囊「照见」** — `MobileShell`：currentPath === "/" 时胶囊显 `common.brand`（链接行为不变）；首页 Hero 的独立 logo+「照见」行删除。桌面竖栏 BellLogo（aria-label=nav.home）不动。

### 发现的既有问题（不属于本批，未动，如实上报）

1. **en 浏览器无 cookie 首访 = 全站 hydration mismatch**。服务端 locale 只认 cookie/x-zj-locale（默认 zh），客户端 `detectLocale` 非中文一律 en——headless 复现：SSR `aria-label="运势"` vs 客户端 `"Fortune"`，React 报错并重生成整树。真实 en 用户首访必踩。建议下一轮处理（服务端加 Accept-Language 解析，或客户端首帧先按 cookie 渲染再切换）。
2. `<html>` 的 `--tg-viewport-height` 内联样式与 CompassWatermark 浮点坐标序列化位数差异（`…91524` vs `…9152`）产生 attribute 级 hydration 警告（dev 下「1 Issue」角标即此），均为既有、非本批引入。
