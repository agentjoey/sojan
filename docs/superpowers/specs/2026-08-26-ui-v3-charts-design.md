## 3. B1 · 五行盘 `WuxingWheel`

`02-components.md` §5 的几何是给死的，照抄：

```
五扇形  r = 118，起始 −126°，每 72° 一扇
        顺序：木(上) 火(右上) 土(右下) 金(左下) 水(左上)
十天干环 r = 138
中心    r = 50，日主大字
日主所属那一扇走强调手法：fill rgba(168,70,56,.08) + 2px 朱砂边
```

- 扇区填充用**五行语义色**（`--color-wood/fire/earth/metal/water`）表达占比，日主那一扇另加朱砂描边——这是「强调只有一种手法」在图形上的对应形态，**不是**第二种强调。
- `rgba(168,70,56,.08)` 是设计包给定的朱砂 rgba 字面值，属 A 块已确立的裸值例外，照抄。
- Props 至少要有：五行计数（`chart.bazi.fiveElementCounts` 的形状）、日主天干、日主五行。**组件不做任何推算**——五行归属、日主五行一律由调用方（core 的既有派生）传入。这是仓库红线：排盘不许在展示层算。
- 无障碍：整体 `role="img"` + `aria-label` 概括（「五行分布：金 3、水 3、木 1、火 1、土 0，日主庚金」），扇区本身不做焦点目标（与 `BaguaWheel` 不同——那里的卦字是可选中的交互元素，这里不是）。

## 4. B2 · 七十二候标尺 `SeasonRuler` + core 候序号

### 4.1 core：候序号函数

标尺要标「第 40 候」和当前位置，需要 1–72 的序号。**`lunar-typescript` 没有直接给**（已探明：`getHou()` 只返回「处暑 初候」这样的字符串）。

序号可确定性推导：24 节气自立春起定序，`候序号 = 节气序 × 3 + 候序`。验证：处暑是第 14 个节气（0-based 13）、初候 → `13×3+1 = 40`，与设计包示例「第 40 候」吻合。

在 `packages/core/src/daily/season.ts` 扩展 `getCurrentSolarHou()` 的返回，增加 `index`（1–72）与 `term`（节气名）。**必须是纯函数 + 静态节气定序表**，不要再去查库算。

⚠️ `packages/core/tsconfig.json` 的 `include` 只有 `["src"]`，写在 `core/test/` 里的类型断言不过类型检查——测试要靠**运行时值比较**。

### 4.2 组件

```
移动端：repeating-linear-gradient(90deg, line-strong 0 1px, transparent 1px 4.55px)  共 72 道
桌面端：刻度间距放大到 8.6px（06-desktop §4），仍是 72 道
当前候：一道 1.6px 朱砂竖线
两端：标「立春 · 第 1 候」与「大寒 · 第 72 候」
```

- 刻度用 `repeating-linear-gradient` 而不是 72 个 DOM 节点——设计包给的就是这个手法，也避免了 72 个空元素。
- 当前候那道朱砂竖线按 `index` 定位（`left: (index-1)/71 * 100%`），不要按日期比例——候是等分的离散刻度。
- 无障碍：`role="img"` + `aria-label`（「七十二候：当前为第 40 候，处暑初候」）。纯装饰的刻度层 `aria-hidden`。

## 6. 风幡图 —— 素材阻塞，本轮不做

`02-components.md` §7 要求：「`assets/windbell-jin.png` 是**烧了字的样例**。实现时拆成『幡面底图（透明 PNG）+ 运行时叠判词』」。

**问题：设计包里没有可用的无字底图。** 已核两张素材：

| 文件 | 尺寸 | 色彩 | 内容 |
|---|---|---|---|
| `windbell-jin.png` | 1254² | RGBA（**有透明**） | 幡面上烧着「谨」字 |
| `windbell-source.png` | 1254² | RGB（**无 alpha**，不透明底） | 幡面上烧着「照见」 |

两张都带字，`source` 还没有透明通道。设计包自己的 `05-open-questions.md` 待定 #1 也正是这条（「底图 + 运行时叠字，还是四张预渲染图？」）。

**处置：本轮挂起，不做替代方案。** 理由：
- 把「谨」字从样例里 P 掉属于伪造设计素材，且质量不可控；
- 纯 SVG/CSS 重绘幡面（红色曲面 + 海浪纹）做得出形、做不出那张图的质感，而本仓库刚刚在掷筊那件事上验证过——手绘矢量到不了参考图的水准；
- 四张预渲染图这条路同样缺素材。

**需要 owner 提供**：一张**无字、透明底**的幡面 PNG（判词由代码叠）。拿到即可单独排一个小任务，不阻塞 B 的其余四项，也不阻塞 C（C 里凡用到风幡的位置先留占位）。

## 7. 测试策略

沿用 A 块口径：**行为/契约测试是资产，几何与样式断言只钉设计包给死的值。**

- **B1**：扇区数量与角度起点、日主那一扇带朱砂描边、`aria-label` 内容随入参变化。⚠️ 不要断言 SVG path 的完整字符串（一改就红且毫无诊断力），断言角度/半径这些**语义参数**。
- **B2**：core 函数——`index` 对已知日期正确（2026-08-25 → 40）、跨节气边界、每个节气的三候连号；组件——当前候竖线位置随 `index` 变化、两端标签、`aria-label`。
- **B3**：默认选中命宫、点另一宫切换详情块、键盘 Enter/Space 可触达、四化图例四色齐、空宫显示借星（若数据可得）。
- **B4**：日柱带竖向 `Emphasis`（`border-top` + `180deg`）、其余三柱不带。
- 关键改动照仓库惯例做 **mutation 复验**。
- ⚠️ 动了 `packages/core` 就要跑 core 与 llm 两个包，不能只跑 web。
