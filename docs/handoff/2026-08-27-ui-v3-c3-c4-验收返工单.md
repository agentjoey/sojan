## 二、必修（阻塞合并）

### C1 · 成本分级标签着色推翻了一次记录在案的 P0 无障碍修复

`apps/web/app/fengshui/page.tsx:603-607, 664`

11px 正文，门槛 4.5:1，纸底 `#f8f6f0`。**验收方独立按相对亮度公式实算**：

| 档 | 令牌 | 值 | 对比度 |
|---|---|---|---|
| 零成本 | `--color-wood` | `#5c9a77` | **3.06:1** ✗ |
| 挪动 | `--color-earth` | `#ce9a4a` | **2.33:1** ✗ |
| 添置 | `--color-line-strong` | `#d8d3c6` | **1.38:1** ✗✗ |
| （改动前）| `--color-muted` | `#716b60` | **4.84:1** ✓ |

⚠️ **关键**：`globals.css:53` 的令牌注释白纸黑字写着——`--color-muted` 这个值是 **2026-08 一次 P0 critique** 专门从 `#9c9486`（2.75:1）提上来的，为的就是过 AA。**本次改动把它换成了三个更差的值，其中 1.38:1 在纸上基本不可见**——那不是「淡一点」，是把一档信息删掉了。

**根因在设计包**：`03-screens.md`「境」节写的就是「零成本 wood / 挪动 earth / 添置 line」，而 `line` 是**分隔线令牌，从来不是文字色**。但开发包 §14 写明「涉及产品语义的选择 → 不要自作主张，在报告里列出选项」，实施报告对此**一字未提**。

**修法**：文字保持 `--color-ink-2`（5.42:1），五行色降级为标签左侧 6px 色点（装饰元素，非文字）；`line-strong` 那档改用 `--color-metal`。

### C2 · 生气方标题与它包住的那句话可能指向两个不同方位

`apps/web/app/fengshui/page.tsx:568`（标题）+ `:554`（基调句）

同一个 `<Emphasis>` 块里：
- 标题用 `shengQiDir` ← `activeVerdicts` ← **随同住人视角切换**
- 块内 `tagline` ← `deriveFengshuiTagline(f.personalDirections, …)` ← **恒取主档案本命**，且方位名被写进句子

于是「视角：某同住人」且两人非同组时，用户看到：

> **生气方 · 西**
> 金命之人，宜近土——你的生气在**东南**。

**一个强调块内两个互相矛盾的方位。** 这是 CLAUDE.md「两套八方不得互推」的同型错误（本人 vs 同住人，机制一样）；而 `tagline` 上方那条既有注释正是为此写的，新代码从它正下方绕了过去。

**修法**：标题固定用 `f.personalDirections` 的生气方（与 tagline 同源），**或**整块随视角走（`deriveFengshuiTagline` 也传 `activeVerdicts`）。**二选一，不能一半一半。** 补一条「切到同住人视角后标题与基调句同源」的断言。

### C3 · 桌面两栏与 `06-desktop §3` 的分栏表**方向相反**

`apps/web/app/fengshui/page.tsx:754`（left）/ `:956`（right）

设计表：**左 440px = 八方盘 + 四吉方说明；右 = 盘/化解/添置 tab 内容 + 同住人对照**。
实现是反的——整个 `tab === "chart"` 面板全在 `left`，`right` 只有 remedy/object 面板。后果：

- **默认进页（tab=盘）在 ≥1200px：右列约 680px 里只有一句 12px 免责句**；左列 440px 里塞两个八方盘 + 全部长文，`.reading-prose` 被压到约 394px，远低于 §3 要求的正文列宽 620px。
- 切到「化解」：左列只剩一行 12px 的四吉方说明，一条 1px 竖线拉满全高。

实施报告给的理由（既有 `compareDocumentPosition` 测试钉死了 DOM 序）**经复核不成立**——那两条测试只钉了基调句一句与两个标题的相对位置，没钉长文。至少两种合规解法：把长文与 tab 内容移右列；或 `left = 房屋八方盘`、`right = 基调 + 叙述 + 本命盘 + tab 内容`。

### C4 · 危机拦截屏不再是「换成求助引导屏」

`apps/web/app/spirit/page.tsx:317`（`left` 无 stage 门控）+ `:340`（注释自陈 crisis 也渲染图区）

`stage.kind === "crisis"` 时逻辑红线完好（不掷、不烧额度、优先短路，既有两条断言仍绿），**但结构被破坏**：262px 筊杯图区 + 三列筊象释义（含 `Emphasis` 高亮）+ 三掷点照旧渲染，求助文案在其后。移动端 402×850 估算，热线号码基本落到首屏之外。三掷点那个 div 还挂着 `aria-label="还可以掷 3 次"`，在危机屏上向读屏用户播报剩余掷筊次数。

`03-screens.md` 原文是「命中即不掷、不烧额度，**直接换成求助引导屏**」——后半句没做到，而现有断言（查文案在场 + `throwJiao` 未调用）在结构上抓不到。

**修法**：`crisis` 时整页早退成引导屏（照 `conversing` 写法），或至少给 `left` 加 `stage.kind !== "crisis"` 门控；补 `expect(screen.queryByTestId("jiao-card")).toBeNull()`。

### C5 · 四吉方断言用了**非锚定**的方位名子串匹配

`apps/web/app/fengshui/__tests__/page.test.tsx:1760-1763`

**验收方实证**：
```
"西南（延年）".includes("南（延年）")  → true
"东北（伏位）".includes("北（伏位）")  → true
```
用例名承诺「**恰**列出坎1 的四吉」，但 `toContain("南（延年）")` / `toContain("北（伏位）")` 区分不了 南/西南、北/东北。把 `auspiciousDirs` 退化成错的一格，这两条不会变红。**这正是 CLAUDE.md 点名、本仓库已咬过三次的嵌套陷阱。**

**修法**：整串比对，顺带钉住 rank 1→4 排序（现在完全没测）：
```js
expect(line.textContent).toBe("四吉方 · 东南（生气） · 东（天医） · 南（延年） · 北（伏位）");
```

## 五、需 owner 拍板（不由实施方决定）

1. **五行色作为文字色系统性不达标**（C1 + I2 的共同根因）。设计包多处指定五行色当文字色，而 wood 3.06 / earth 2.33 / gold 2.48 / metal 均低于 4.5:1。建议 owner 给一条**全局规则**——例如「五行色只作装饰（色点/边框/底），不作文字色；需要着色文字时用 `ink`/`ink-2`/`cinnabar`」——否则 D 块与后续都会反复踩。
2. **`en.nav.spirit = "掷筊 (Jiao)"`** 与同级导航项体例不一致（其余六项 `Home / Fortune / Chart / Feng Shui / Dream / Me` 全英文）。`nav.*` 是 UI chrome，不属「命理术语保持中文」的范围（`Feng Shui` 即先例）；该键还兼任移动端语境胶囊默认文案，中英混排在 82px 竖栏与 44px 胶囊里都最挤。建议 en 用 `"Jiao"`，zh 不动。
